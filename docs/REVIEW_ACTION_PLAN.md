# Review response and priority order

This is a paraphrased technical action plan based on the user-provided AAAI reviews and independent repository checks on 2026-11-01. Confidential correspondence is not reproduced. The two human reviews and the separate AI review are distinct sources; an automated comment is not an additional human reviewer. Reviewer opinions are assessed against code and evidence rather than treated as established facts.

The current evidence does not support a competitive method submission with the historical claims. The strongest direction is an **audit-led benchmark paper**, conditional on a defensible rebuild and new evaluations. A method paper becomes plausible only after matched controls show reproducible gains. None of these changes guarantees acceptance.

| Priority | Concern and supporting evidence | Corrective action / experiment | Completion evidence |
|---|---|---|---|
| **Blocking 1** | Test-based stage/alpha selection (historical main Tables 2, 6; supplement S9); extension's 800 evaluation paths also appear in training ([release audit](evidence/release_data_audit.json)); source-family leakage in the older protocol ([census](evidence/audit/census.md)) | Group scans, derived edits, known patients and duplicates before splitting. Freeze train/select/test and train's SFT/RL pools. Apply exclusions to every replay/control. Use only selection results for model choice; retrain/evaluate under the corrected protocol. | Zero cross-split identity/component overlaps; reported unknown-patient coverage; hashed manifests and candidate plan; selection decision before final test inference. | **Blocking 2** | Kidney/colon labels correlate with source, editor and format; JPEG implants versus PNG others; duplicated colon normals ([expansion audit](evidence/audit/expansion.md), [shortcut audit](evidence/audit/shortcut.md)) | Rebuild from matched source populations; case/video grouping; canonicalize real and fake identically; multiple editors per edit type; leave-one-editor-out tests. | **Minor after blockers** | Presentation, names, figures, protocol diagrams, template compliance | Add a single protocol table; distinguish scan/file/group/patient counts and selection/test; improve figures and captions; check the current venue instructions at submission time. | Consistent manuscript/repo, link/table checks and final policy/template review. |

Work order: protocol and lineage → plain SFT/constant controls → balanced continued SFT versus RL → extension rebuild/editor controls → unseen-organ evaluation → manuscript rewrite. Clinical review recruitment and data-rights work should proceed in parallel with engineering. Do not spend the next cycle only tuning alpha on existing public test results.
